# Запрет заказов для Telegram-аккаунта

Новый запрет относится к Telegram ID, а не к имени, username или сессии.
PostgreSQL хранит записи в `order_blocked_telegram_users`; перед вставкой
нового заказа или дозаказа база проверяет этот список. Повторный вход и смена
username не снимают запрет. История заказов и бронирование не меняются.

Приложение получает обычную ошибку `INTERNAL`, без сообщения о запрете. Заказ,
его позиции и уведомления при отказе не создаются. Сейчас включена только оплата
наличными. Перед будущим подключением онлайн-оплаты проверку нужно проводить до
создания платёжной ссылки и списания; ошибки после оплаты недопустимы.

Административное добавление выполняется транзакционно: заблокировать строку
пользователя `SELECT ... FOR UPDATE`, вставить его Telegram ID, автора и причину
в `order_blocked_telegram_users`, затем записать действие в `audit_log`.
Чтобы отменить запрет, требуется отдельное решение ADMIN, удаление конкретной
записи и новая запись аудита. Запрет не связывает разные Telegram-аккаунты
одного человека.

Миграция: `backend/migrations/062_order_blocklist.sql`. Проверка на чистой
тестовой PostgreSQL: `TestOrderBlockPreservesHistoryAndRejectsNewOrdersAndAdditions`.
