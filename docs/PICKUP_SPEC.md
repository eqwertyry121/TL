# Самовывоз по времени — техническое задание

## Цель

Клиент заранее выбирает время, к которому блюдо должно быть горячим и готовым.
Кухня не путает самовывоз с доставкой, видит приоритеты и выдаёт готовый заказ
без участия курьера.

## Клиентский сценарий

1. В оформлении клиент выбирает `Доставка` или `Самовывоз`.
2. Для самовывоза показываются адрес ресторана, ссылка на карту и только
   доступные слоты текущего рабочего дня.
3. Первый слот начинается не раньше `сейчас + время на приготовление`.
4. Выбранный слот обязателен. Без него кнопка оформления недоступна.
5. Телефон обязателен. Для наличных действует та же Telegram-проверка
   местоположения, что защищает доставку от удалённых ложных заказов; точная
   координата после проверки не хранится.
6. После создания экран заказа показывает время и адрес самовывоза.
7. Когда кухня нажимает `ЗАКАЗ ГОТОВ`, клиент получает сообщение. Заказ остаётся
   активным, пока сотрудник не нажмёт `ЗАБРАН И ОПЛАЧЕН` для наличных либо
   `ЗАБРАН` для уже оплаченного заказа.

Самовывоз не является общим предзаказом: доступен только на текущий рабочий
день и только пока backend принимает заказы.

## Расчёт слотов

Backend — единственный источник доступности. `GET /api/v1/pickup/slots`:

- использует серверное время `Europe/Belgrade`;
- проверяет график, ручной `ВЫХОДНОЙ` и `pickup_enabled`;
- округляет первое допустимое время вверх до шага слота;
- не отдаёт время позже `pickup_last_time`;
- исключает слот, если число активных pickup-заказов достигло лимита;
- возвращает ISO timestamp, подпись времени и оставшуюся вместимость.

При создании заказа backend повторяет проверку внутри транзакции и берёт
advisory lock на выбранный слот. Поэтому два одновременных клиента не могут
занять последнее место. Ошибка занятого/устаревшего слота возвращается как
конфликт, после чего клиент обновляет список времени.

Начальные настройки:

- подготовка: 40 минут;
- шаг: 15 минут;
- максимум: 3 заказа на один слот;
- последний самовывоз: 22:00;
- адрес и ссылка на карту редактируются ADMIN.

## Статусы и права

Самовывоз использует отдельную цепочку:

`NEW → READY_FOR_PICKUP → DELIVERED`

- Kitchen: `NEW → READY_FOR_PICKUP` кнопкой `ЗАКАЗ ГОТОВ`.
- Kitchen: `READY_FOR_PICKUP → DELIVERED` кнопкой `ЗАБРАН И ОПЛАЧЕН` для
  наличных либо `ЗАБРАН` для уже оплаченного заказа. Для наличных действие
  одновременно фиксирует `payment_status=PAID`.
- Courier никогда не получает и не видит pickup-заказы.
- ADMIN может отменить активный заказ или вернуть готовый заказ в `NEW` с
  обязательной причиной.
- Клиент не может создать второй заказ, пока первый находится в любом активном
  статусе.

## UX кухни

На мобильном экране сверху две вкладки с количествами: `ДОСТАВКА` и
`САМОВЫВОЗ`. На планшете/компьютере они видны одновременно в двух колонках.

Самовывоз разделён на три компактные группы:

1. `ГОТОВЫ К ВЫДАЧЕ` — самые заметные карточки и кнопка
   `ЗАБРАН И ОПЛАЧЕН`/`ЗАБРАН`.
2. `ГОТОВИТЬ СЕЙЧАС` — полные карточки, блюда сразу видны, одна основная кнопка
   `ЗАКАЗ ГОТОВ`.
3. `ПОЗЖЕ` — компактные строки: время, номер, клиент и состав. Они не занимают
   экран, пока не приблизится время приготовления.

Новый заказ отмечается непрочитанным. Переход из `ПОЗЖЕ` в
`ГОТОВИТЬ СЕЙЧАС` происходит автоматически по часам интерфейса. Просроченное
время выделяется визуально, но статус самопроизвольно не меняется.

## Админка

В настройках доступны:

- включить/выключить самовывоз;
- адрес и ссылка на карту;
- время подготовки;
- шаг слотов;
- максимальное число заказов на слот;
- последний слот;
- короткая инструкция RU/SR/EN.

Изменение настроек влияет только на новые заказы. В каждом созданном заказе
хранятся снимки выбранного времени, адреса и инструкции, чтобы история не
менялась задним числом.

## Данные и безопасность

В `orders` сохраняются `pickup_at`, первоначальное выбранное время и snapshots
адреса/инструкции. Цена по-прежнему считается только backend. Создание заказа
защищено `Idempotency-Key`, уникальным активным заказом на клиента и
транзакционной проверкой вместимости слота.

## Acceptance criteria

- Нельзя создать pickup-заказ без времени, в прошлом, после последнего слота
  или в заполненный слот.
- Два конкурентных запроса не превышают лимит слота.
- Pickup не попадает курьеру и не раскрывает ему контакт клиента.
- Кухня видит все блюда, время и три группы приоритетов.
- После `ЗАКАЗ ГОТОВ` клиент уведомлён, заказ остаётся у кухни до подтверждения
  получения и, для наличных, оплаты.
- В активный заказ можно сделать только разрешённый дозаказ до времени начала
  приготовления.
- Перезапуск приложения восстанавливает выбранный тип получения и слот до
  завершения оформления.
- ADMIN может мгновенно отключить новые pickup-заказы без влияния на уже
  созданные.
